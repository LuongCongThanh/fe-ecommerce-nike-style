# Requirements Traceability Matrix

> File này không thay thế [`../requirements/functional-requirements.md`](../../00-core/requirements/functional-requirements.md). Nó chỉ map requirement hiện hành sang product, design, test, metric và các khoảng trống còn tồn tại.

## Mục đích

- Cho biết mỗi requirement MVP hiện đã được nối tới những tài liệu nào.
- Làm rõ requirement nào đã có design/test/metric, requirement nào còn thiếu.
- Lộ ra sớm các chỗ conflict giữa `requirements/`, `product/`, `architecture/`, và `planning/reference/`.

## Cách dùng

- Nếu scope đổi: sửa [`../requirements/functional-requirements.md`](../../00-core/requirements/functional-requirements.md) trước, rồi cập nhật matrix này.
- Nếu design đổi: cập nhật cột `Design refs`, `Domain/API refs`, `Test refs`.
- Nếu cần biết test case cụ thể thay vì chỉ tài liệu test tổng quát, xem [`./test-traceability-matrix.md`](test-traceability-matrix.md).
- Nếu phát hiện một requirement chưa có test hoặc metric: đánh dấu ở cột `Gap / status` thay vì bỏ qua.
- Nếu một requirement đang có mâu thuẫn giữa các tài liệu: ghi rõ `Conflict`, không tự chọn một bên ở file này.

## Quy ước ID

- `SF-*`: Storefront requirement
- `AD-*`: Admin requirement
- `CMS-*`: CMS requirement
- `NFR-*`: Non-functional requirement
- `SEC-*`: Security/privacy/control requirement

Các ID dưới đây là ID làm việc đầu tiên cho bộ tài liệu hiện tại. Khi wording thay đổi, nên giữ nguyên ID nếu ý nghĩa requirement không đổi.

## Trạng thái

- `Covered`: đã có đủ dấu vết chính từ requirement tới design/test hoặc metric
- `Partial`: đã có một phần coverage nhưng còn thiếu ít nhất một lớp quan trọng
- `Conflict`: có tài liệu đang nói không khớp nhau
- `Gap`: chưa có coverage đủ dùng
