# Decision Log — Nền tảng E-commerce mới (FE)

> Tách từ [`brainstorm-session.md`](../99-reference/planning/brainstorm-session.md) khi phần decision log trở nên quá dài để nằm chung với narrative. File này chỉ giữ hai thứ: quyết định đã chốt và lý do chọn. Nếu cần bối cảnh dẫn tới quyết định, xem lại `brainstorm-session.md`.

## Cách dùng tài liệu này

- Tìm ở đây khi cần biết một quyết định đã được chốt hay chưa.
- Nếu một quyết định đã có ở đây, các tài liệu phía dưới không được tự ý đi ngược lại.
- Nếu cần bối cảnh, giả định hoặc tranh luận dẫn tới quyết định, quay lại [`brainstorm-session.md`](../99-reference/planning/brainstorm-session.md).

## Lối vào nhanh

- Nếu bạn đang hỏi về scope nền tảng ban đầu: xem Decision `#1–#11`.
- Nếu bạn đang hỏi về i18n, locale, typography: xem Decision `#14–#19`.
- Nếu bạn đang hỏi về auth, token, state, testing, performance: xem Decision `#20–#28`.
- Nếu bạn đang hỏi về cấu trúc code và quy ước repo: xem Decision `#29–#34`, `#46–#49`.
- Nếu bạn đang hỏi về domain commerce như cart, wishlist, order, return: xem Decision `#35–#45`.

## Cụm quyết định chính

- `#1–#11`: hướng đi sản phẩm, mock-first, foundation-first, và vai trò của tài liệu tham khảo.
- `#12–#13`, `#29–#34`, `#46–#49`: kiến trúc monorepo, package boundary, naming, import rule, và quy ước scaffold.
- `#14–#19`: domain locale/i18n.
- `#20–#28`: auth, design token, state, API mocking, testing, performance.
- `#35–#45`: domain model commerce cốt lõi.
- `#50`: mock catalog data spec (quy mô, không phải domain model — domain model catalog đã chốt ở `glossary.md`).
- `#51–#54`: developer-experience tooling (ESLint plugin set, git hooks/commit lint, Zustand devtools, bundle analyzer).
- `#55–#56`: mở rộng naming convention và nâng mức ESLint TypeScript ruleset.
- `#57`: bỏ barrel `index.ts` (thay thế phần barrel của #29), export package qua `package.json` `"exports"` subpath, alias-only import.
- `#58`: PWA (`next-pwa`), production-only để tránh xung đột service worker với MSW.
- `#59`: 3D visualization (Three.js) chỉ ở storefront PDP.
- `#80–#83`: pivot multi-repo rồi quay lại monorepo, và các gap phát hiện khi wire code thật (breakpoint, ESLint boundaries).
- `#84–#85`: gap contract Product/Cart chưa khớp glossary; #85 chốt lại Product/Category theo glossary ngay ở issue #9, Cart vẫn hoãn.
- `#86–#88`: hardening commit/CI, giới hạn MSW+Next.js App Router fetch caching (SSR), và PDP Variant→SKU + 3D viewer (issue #10).
- `#86`: no-AI-attribution + lint/build chuyển từ convention văn bản sang chặn kỹ thuật (git hooks + CI).

## Ghi chú

- Đánh số quyết định là liên tục, không tái sử dụng lại số cũ khi một quyết định bị đảo ngược — nếu một quyết định thay đổi, thêm dòng mới, ghi chú "thay thế Decision #N" trong cột Lý do chọn.
- Những quyết định có trade-off lớn hoặc cần lập luận riêng sẽ được tách thêm thành ADR trong [`docs/00-core/adr/`](adr/).
- Khi một quyết định đang được dùng hằng ngày ở code hoặc test, ưu tiên link thẳng tới số quyết định liên quan thay vì bắt người đọc đọc lại toàn bảng từ đầu.
